START HACK MUNICH 2026 — PROJECT ARCHITECTURE
================================================

Purpose
-------
This folder contains the Differometor optical/interferometer simulator, example
models and data, and the START Hack benchmark harness. The benchmark exercises
one saved UIFO optical setup end to end, including a forward solve and gradient.

OPERATIONAL ENTRY POINTS
------------------------

1. Full reproducible benchmark

   Command:
     python benchmark.py --output benchmark-baseline.json

   On Linux/WSL, optionally add --cpus N to pin the process to N allowed logical
   CPUs. Native Windows does not support this option in the script.

   Call/data flow:

     benchmark.py
       -> sets CPU/JAX environment options before importing numerical libraries
       -> imports JAX, NumPy, and differometor
       -> reads examples/data/uifo_800_3000.json
       -> reads examples/data/uifo_800_3000_test_data.json
       -> validates fixture content hashes (CRLF is normalized to LF)
       -> differometor.setups.Setup.from_data(...)
       -> differometor.setups.constrain_inter_grid_cell_spaces(...)
       -> differometor.simulate.run_build_step(...)
       -> JAX compiles and calls differometor.simulate.simulate(...)
       -> differentiate simulation with jax.vjp
       -> readout via differometor.components.signal_detector and power_detector
       -> compute sensitivity, scalar loss, and reverse-mode gradient
       -> repeat warmed evaluations; validate outputs and finite-difference gradient
       -> writes JSON timing/validation report
       -> imports plot_timings.render(...) and writes the timing chart

   Important: benchmark.py performs a fixed evaluation, not an optimization loop.
   Default is 10 warm repeats. It creates a PNG beside the JSON unless --plot is
   provided; --save-arrays optionally writes evaluated arrays as NPZ.

2. Short demonstration

   Command:
     python start_here.py

   start_here.py loads the same saved UIFO fixture and reference, builds the
   simulation arrays, defines the sensitivity/loss function, compiles
   value_and_grad as one JAX function, then evaluates once and prints timings.
   It is a compact walkthrough and is not directly timing-comparable to the
   staged full benchmark.

3. Plot an existing benchmark report

   Command:
     python plot_timings.py benchmark-baseline.json --output benchmark-baseline.png

   plot_timings.py reads benchmark JSON only; it does not run the simulator.
   It checks the phase set and total, groups measured phases into five bars,
   and renders a PNG, SVG, or PDF.

SIMULATOR MODULE FLOW
---------------------

  differometor/__init__.py
    Public package exports: Setup; run/build/simulate helpers; visualization;
    detector readout functions.

  differometor/setups.py
    Defines Setup and constructs/loads optical component graphs (nodes and
    edges). Also provides setup factories such as UIFO/Voyager and parameter
    grouping helpers used for optimization.

  differometor/build.py
    Converts a Setup graph into carrier, signal, and noise system matrices,
    parameter vectors, detector/port metadata, and indexed update instructions.
    Component math is supplied by components.py.

  differometor/simulate.py
    run_build_step() calls build(), turns its instructions and matrices into
    named JAX arrays matching simulate()'s arguments. simulate() updates the
    matrices for current/swept/optimized parameters, solves carrier and signal
    systems, propagates quantum noise, and returns carrier, signal, and noise.
    run_simulation_step() and run() are convenience wrappers.

  differometor/components.py
    Physical/component functions (spaces, lasers, mirrors, beamsplitters,
    mechanical effects, noise and detectors) used by build instructions and
    detector readouts.

  differometor/utils.py
    Higher-level sensitivity, power, bounds, and optimization utilities used
    mainly by example workflows.

  differometor/plot.py
    Interactive Plotly visualization of an optical setup; exported as
    differometor.visualize_setup.

EXAMPLE SCRIPTS
---------------

The scripts in examples/ are independent workflows, not invoked automatically
by benchmark.py:

  aligo.py / cavity.py          Build and run example optical systems.
  uifo.py                       Evaluate/visualize Voyager and saved UIFO setups.
  voyager.py                    Voyager example workflow.
  uifo_optimization.py          Builds multiple UIFO variants, evaluates an
                                objective and gradients, then runs Optax Adam.
  voyager_optimization.py       Voyager optimization example.

Typical example flow is: create/load Setup -> df.run(...) or run_build_step()
plus simulate() -> detector/sensitivity/power utilities -> optional visualization
or plots. Optimization examples wrap this evaluation in JAX differentiation and
an Optax update loop.

DEPENDENCY / RUNTIME NOTES
--------------------------

  Python entry scripts -> differometor package -> JAX/JAX NumPy computation
  Plot output          -> Matplotlib (benchmark chart); Plotly (interactive setup)
  Optimization demos   -> Optax

The benchmark forces the CPU backend and enables 64-bit arithmetic before
initializing JAX. Its measured first-run total includes imports, CPU
initialization, input preparation, tracing/lowering/compilation, execution,
gradient calculation, and host transfer. Validation and report/plot generation
are outside that total.
