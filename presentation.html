1:00 — THE SOLUTION

Keep the physics.
Change the computation.

We optimized the path around the model: less work to compile, fewer dense operations, and one fused evaluation-and-gradient executable.

01 / COMPILE

Group component work

Evaluate each component type over its own calls instead of dispatching every call through a large switch.

02 / SOLVE

Exploit sparsity

Represent signal and noise systems by nonzero values; share sparse LU work for signal and detector-weight solves.

03 / DIFFERENTIATE

Fuse value + gradient

Compile one combined simulation, readout, and reverse-mode function instead of three staged executables.

NumPy host kernels for component coefficients Lazy plotting imports UIFO build logic largely preserved

Talk track · 1:00–1:45

We kept the component equations and focused on how they run. First, group like component calls so the compiler doesn’t carry unnecessary branch work. Second, store the mostly-zero signal and noise systems sparsely, and reuse sparse factorization work. Third, wrap simulation and readout in one value-and-gradient function so JAX builds one executable for the main calculation. The UIFO setup-building logic itself is largely unchanged; the bigger gains are in compilation and simulation, not in constructing the fixture.

Talk track · 1:45–3:00

This report opens up every one of the 30 fresh-process runs. The first run took 2.104 seconds; runs two through thirty averaged 1.518 seconds, so the first-run excess was about 0.585 seconds. The report attributes that excess by phase: imports, setup building, and compilation account for about 85 percent of the difference. Important caveat: that is measured attribution, not proof of the underlying cause. Fresh Python processes do not clear operating-system or shared-library caches. The remaining runs are tightly grouped around the mean, and all 30 passed the supplied benchmark checks. The full report includes each run’s phase timings, sample methodology, and exact source data. Our takeaway: the speedup is repeatable across fresh process launches, while the report also makes first-run effects visible instead of hiding them. Thank you.
